# 水灾、天气特效和原生避难修正

> 后续版本已修正水源跨堤、河道扩展、预警和动画问题，当前实现与验证边界以 [效果全面修正](效果全面修正.md) 为准。下文保留各阶段历史记录。

日期：2026-10-06。用户要求修复海啸、洪水无效果，核对原生避难，以及冰雹、雷击缺少动画。当前为增强版候选；旧候选已测到局部涨水，增强版仍待实机复测。

## 首轮修复的根因与改动

- 当前城市原存档的 `WaterSystem.UseLegacyWaterSources=false`。新版 `WaterSimulation.SourceJob` 不读取 `WaterLevelChange`；升级还会删除旧海水源实体。旧实现创建了灾害事件，却没有影响新版实际水体计算。
- 新增 `WaterDisasterSystem`，在原生水源缓存完成重建后加入事件高度偏移；首个候选版海啸只在所选上游地图边缘的现有海水区域施加造波。仅修改临时计算缓存，不改水源 ECS 实体、不修改全局海平面。旧水体继续走游戏已有灾害路径。
- 触发前检查方向是否有可用水源，没有则提示换方向。洪水排除排水、污水和零半径来源；停止和到期不再向缓存施加灾害变化，已存在的水流仍由游戏传播。
- 手动冰雹事件没有设置原生气候的 `hail`，原生降水渲染不会显示冰雹。新增独立的原生 `Precipitation/PrecipitationVFX` 实例，镜头处于受灾区域时发送 `OnHailStart`，离开、停止、加载时关闭或销毁；不改变全城气候。
- 原版雷击间隔为 60 秒，短于这一间隔的手动事件可能结束前没有雷击；原生闪电队列还要求命中建筑或树木。手动变体改为首轮约 1 秒、后续间隔 3–8 秒；无建筑/树木时，仅向原生闪电队列补空地特效。渲染代码不实施伤害或起火。
- 庇护所一直由游戏原生选择。之前的 Mod 还直接重写了在外居民的 `TripNeeded`、`TravelPurpose` 等状态；本次删除该干预。Mod 只发出原生 `Endanger` 警报，后续由 `CitizenEvacuateSystem`、`InDangerSystem` 及原生庇护所/交通处理。默认按受灾范围警报；全城警报仍是用户明确选择的功能。

## 首轮已验证的边界

- Release 和 Debug 编译无错误、无警告。
- 离线水灾计算覆盖预警帧、渐升、方向、海水与内陆水体区分、前导回落、停止与到期；这些检查不代表 GPU 水体实际效果。
- 浏览器面板回归通过，包括受灾范围默认选中、原生处理说明、方向、强度、停止与重复触发保护。
- 在本机游戏资源中查到原生冰雹/闪电 VFX 事件名和参数。检查了新版 `AddConstant` GPU 程序，确认它按目标高度更新水深，没有直接排除海水区域；仍需实机测量传播效果。
- 没有修改原存档，没有操作用户的游戏会话。本轮检查时游戏进程和两个调试接口都已退出。

## 实机验收仍需完成

1. 从城市副本测量洪水/海啸前后的 `SurfaceWater` 深度，不能仅依据事件、强度或缓存计数宣布通过。
2. 当前候选版海啸点击想冲击的岸边区域，观察自动选取海水附近的波前、向岸传播与实际水深；核对停止或造波时间结束后不再造波，尾波自然传播。
3. 镜头进入冰雹受灾范围，观察粒子；空地雷击与建筑/树木雷击分别观察，避免重复特效；核对暂停、停止、换城清理。
4. 从危险建筑观察原生居民避难、庇护所容量与巴士，不用旧版直接改写居民行程后的数据代替。

新版水体适配依赖本机 1.6.2f1 的两个私有缓存成员，启动时检查它们是否存在。其他游戏版本需重新核对。实际波高与传播仍受地形、水深和水体模拟影响。

## 手动测试后的海啸定位修正（中间候选）

2026-10-06 03:35 的日志确认 10 级海啸事件创建成功。03:37:55 至 03:41:54 的两次全图只读采样中，城区北侧水域最大水深增加仅 0.01 米，南缘最大增加 5.69 米、最大下降 21.1 米。这不是触发前后基线，不能将边缘变化直接归因于海啸。代码确认首版造波点固定在地图边缘，用户点击位置未参与定位。

后续候选改为：新版水体必须点击现有海水，在点击位置上游 224 米采样横向波前；上游中心是陆地时退回点击位置；水源中心排除陆地和地图外位置。使用每个事件独立的波前缓存，仍由原生水体处理上涨、扩散和漫岸。首次写入缓存记录事件、选点、方向、来源数量和初始偏移，供只读复核；该日志本身不代表 GPU 水位已经验证。

达到用户设定的造波时间后自动进入尾波阶段。面板分别显示剩余造波秒数与“尾波传播中”，避免把整个传播等待时间显示成还在造波。

该中间候选完成时游戏仍在运行，其 DLL 未替换。只做了离线计算、构建和面板回归；实测波高、传播和漫岸尚待用户手动复测。

## 本轮水灾简化与视觉增强

用户澄清洪水、海啸整体过于复杂，并要求改善地震、陨石动画。当前候选在原有系统中作以下调整：

- 洪水、海啸只显示强度和时长。选类型后直接点击想影响的位置，无需选择方向、原始水源、预警或警报范围。
- 新版水体在点击点 4096 米内粗搜并细化附近现有水面；海啸只接受海水。点击陆地时朝点击位置推进，点击水面时朝 1024 米内最近岸边推进，无岸时使用默认方向。旧水体继续用最近兼容原生水源。
- 新版洪水在所选水面附近加入临时恒定水深源，以触发时水面高度为基线逐渐抬升；不再依赖原始水源实体。海啸保留上游横向波前和造波/尾波阶段。停止或到期后不再向重建缓存添加源，已有水流继续由原生模拟处理。
- 地震添加三轮地面扬尘、碎片和逐步延伸的地表视觉裂纹，裂纹不改写地形或道路。陨石添加加速坠落、火焰尾迹、撞击闪光、抛射碎片和上升扩散烟尘；零预警也保留至少 3 模拟秒的坠落。
- 视觉沿用模拟帧计时，不改变玩家镜头。共享程序生成的透明纹理和网格，最多同时显示 8 场；冲击后 14 秒内消散，停止、加载和销毁时清理。透明混合参数核对了 [Unity HDRP 原生实现](https://github.com/Unity-Technologies/Graphics/blob/2022.3/staging/Packages/com.unity.render-pipelines.high-definition/Runtime/Material/Unlit/BaseUnlitAPI.cs)，实际着色效果仍待游戏中观察。

本轮离线检查覆盖 49 个边界，包括水域查找/方向、涨水/停止/到期和陨石/地震视觉时序。用之前只读取得的水深网格作输入，能为城区点击点找到北侧海水；这是记录数据上的选点检查，不代表新候选已在游戏施加水位变化。浏览器检查确认两种水灾没有方向、预警和范围控件，只有强度和时长，并保存模拟面板截图。

游戏继续由用户手动操作，代理只读观察；源码修改、构建和游戏退出时备份安装不改变此约束。本轮尚未启动游戏或触发灾难。实际漫岸、水位变化、烟尘透明度、动画观感及暂停/停止清理仍需手动验收。
